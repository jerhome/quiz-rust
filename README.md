# Quiz Rust

A desktop quiz game written in Rust with [egui](https://github.com/emilk/egui). Questions are generated on the fly by the Claude API from the topics you choose. Play solo or against others on the same local network.

<!-- screenshots: added after v0.3.0 -->

## Features

- Questions generated by the Claude API: pick a topic from the catalogue or type your own.
- Configurable difficulty and number of questions (5 to 20).
- French and English, for both the interface and the questions.
- Solo mode and LAN multiplayer (one host, several players).
- Every generated question is validated (4 distinct choices, valid answer index, non-empty text); invalid ones are discarded.
- Only the host needs an Anthropic API key.
- The host is authoritative on score and timer. The correct answer is never sent to players before the reveal.
- No OpenSSL dependency (TLS through rustls).
- **v0.3.0+**: players can join from a phone browser by scanning a QR code, with nothing to install.

|---|---|
| `quiz-rust-linux-x86_64` | Linux (X11 by default, Wayland selectable in Settings; also runs in WSL2 via WSLg) |
| `quiz-rust-windows-x86_64.exe` | Windows 10/11 |

On Linux, make the file executable before running it:

```bash
chmod +x quiz-rust-linux-x86_64
./quiz-rust-linux-x86_64
```

The Wayland choice is applied at the next start, with an automatic fallback to X11 if Wayland is unavailable.

## Quick start

### API key (host and solo players)

The app reads the key from the `ANTHROPIC_API_KEY` environment variable, or you can enter it in the app. If you choose to save it, it is stored in `~/.config/quiz-rust/config.toml` (permissions `600`) on Linux, or `%APPDATA%\quiz-rust\config.toml` on Windows. The default model is `claude-haiku-5-5` and can be changed in Settings.

### Solo

1. Launch the app and choose a topic (catalogue or custom).
2. Set the difficulty, number of questions and language.
3. Start the quiz, answer each question, and read the explanation shown at each reveal.

### Host a LAN game

1. Make sure the host machine has an API key configured.
2. Choose the multiplayer host option, then set up the quiz as in solo mode.
3. The lobby shows the host address (`IP:port`, with a Copy button) and, from v0.3.0, a QR code for phones.
4. Start the game once everyone has joined.

### Join from a desktop

- Games announced on the LAN are discovered automatically; pick one from the list.
- Otherwise, type the host address shown in the host lobby (`IP:port`, default port `7878`).

All desktop players must run the same version of the app (network protocol version 5 on the current main branch).

### Join from a phone (v0.3.0+)

1. Connect the phone to the same network as the host.
2. Scan the QR code shown in the host lobby with any camera app (iPhone Safari, Android, or any modern browser).
3. Enter a name and play. Nothing needs to be installed; the page can optionally be added to the home screen.

If the phone locks or the connection drops, the page reconnects automatically and the player keeps their score (the seat is kept for 10 minutes). Desktop and web players can be mixed in the same game. Phones can join a game but cannot host one.

## Network requirements

| Port | Protocol | Purpose |
|---|---|---|
| 7878 | TCP | Game connection (desktop players) |
| 7879 | UDP | Discovery broadcast (the host announces itself every 2 s) |
| 7880 | TCP | Web players: page and WebSocket (v0.3.0+) |

Only the host needs to accept incoming connections on these ports. All participants must be on the same local network.

## Troubleshooting

- **Windows host blocked by the firewall**: allow the app when Windows prompts. On managed PCs this needs administrator rights. Hosting from a Linux machine avoids the issue.
- **Nobody sees the game in the list**: corporate Wi-Fi often blocks discovery broadcasts or device-to-device traffic. Use manual address entry, or a network that allows local traffic.
- **Colleagues cannot reach the host**: disconnect the VPN on the host machine. The lobby flags VPN and virtual network addresses.
- **A player vanished**: lost connections are detected by a heartbeat within about 15 to 20 seconds, so the game no longer waits for them. Phone players reconnect automatically and keep their score.
- **Version mismatch**: desktop clients with a different protocol version are refused. Update everyone to the same release.

## Build from source

Requires a stable Rust toolchain. On Ubuntu/Debian (including WSL2):

```bash
sudo apt install build-essential pkg-config libx11-dev libxcursor-dev libxrandr-dev \
  libxi-dev libxkbcommon-dev libxkbcommon-x11-dev libgl1-mesa-dev

cargo run -p quiz-app --release
```

Cross-build the Windows executable from Linux/WSL:

```bash
sudo apt install mingw-w64
rustup target add x86_64-pc-windows-gnu
cargo build -p quiz-app --release --target x86_64-pc-windows-gnu
```

Run the tests, lints and format check:

```bash
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

No test calls the real Claude API; HTTP is mocked with `wiremock`.

## Project structure

| Crate | Role |
|---|---|
| `crates/quiz-core` | Pure domain: questions, quiz, score, state machine. No I/O. |
| `crates/quiz-llm` | Claude API client; structured output through a forced tool call, plus question validation. |
| `crates/quiz-net` | LAN host, client and discovery; web/WebSocket server for phone players. |
| `crates/quiz-app` | egui application, plus the embedded web player page in `crates/quiz-app/web/`. |

Dependencies flow `quiz-app` to `quiz-llm` and `quiz-net`, then to `quiz-core`; `quiz-core` depends on no other workspace crate.
